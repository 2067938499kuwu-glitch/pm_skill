# V2 发布检查清单

## 加载与执行门禁

- [ ] 项目内存在同名 Skill 时已优先使用项目版本
- [ ] Skill 和必要引用文件均以 UTF-8 正常读取
- [ ] 出现乱码时已停止任务动作并重新读取，没有猜测指令
- [ ] 默认标准模式没有被无理由降级
- [ ] 快速模式每轮最多 3 问；标准/深度通常 1—3 问，仅同一决策无法压缩时最多 5 问
- [ ] 没有把局部确认或零散答复表述为完整需求交付
- [ ] 已识别评审诊断、需求方案、原型说明、Codex 提示词或 Demo，没有自动附加未要求的内容
- [ ] 需求可能涉及已有系统时，已让用户自主选择关联项目分析或不关联项目分析
- [ ] 用户已明确选择时没有重复询问；未明确选择时没有替用户擅自决定
- [ ] 项目关联选择与同轮业务问题合计没有形成大表单，且用户选择前没有读取项目

## 对话与追问

- [ ] 没有重复追问用户、文档、截图、页面或代码已提供的信息
- [ ] 没有把九步内部框架执行成强制九轮对话
- [ ] 简单需求会合并相关步骤
- [ ] 每轮问题数量和相关性符合当前模式
- [ ] 用户回复“不知道”时已提供低风险可逆选项
- [ ] 用户要求停止时没有继续追问
- [ ] 多轮或决策变化时已输出账本版本、覆盖的旧结论和受影响编号

## P0 与停止条件

- [ ] 没有错误扩大 P0
- [ ] 每个 P0 都符合根本性差异标准之一
- [ ] 默认排序、导出、批量操作、弹窗/抽屉和视觉细节没有被自动标记为 P0
- [ ] 停止追问依据闭环条件，而不是完整度百分比
- [ ] 没有因尚未写完所有 Given/When/Then 而继续追问
- [ ] 快速模式两轮后仍有 P0 时已升级标准模式或输出带阻塞草案

## 方案与输出

- [ ] 快速、标准、深度输出已明确区分
- [ ] 没有在简单需求中输出过重模板
- [ ] 已标记已确认、合理假设、待确认、P0 和不在本期
- [ ] 已覆盖核心成功、关键失败和权限差异
- [ ] 已说明实施范围和未覆盖范围
- [ ] 已生成可测试的核心验收标准
- [ ] 标准/深度方案中的 G、R、C、I、AC 有可核验的关联
- [ ] 非页面需求使用 API、流程节点、规则文档或线下触点作为交付载体，没有强行生成页面
- [ ] 正式页面需求方案完成后，对尚未决定的提示词和能力复盘提供一次后续输出选择，用户选择前没有自动生成
- [ ] 非页面需求没有提供页面提示词选项；用户已明确选择或拒绝时没有重复询问

## 已有系统与变更

- [ ] 没有把项目关联方式当作 P0，也没有把“不关联项目”自动判定为全新需求
- [ ] 关联项目分析时已记录可确认的分析基线、分析范围和证据位置
- [ ] 已记录工作区 clean/dirty、相关文件 SHA-256，并在正式输出前复核证据漂移
- [ ] 不关联项目分析时没有扫描项目，且已标记 AS-IS 和项目影响未经核验
- [ ] 没有把现有代码自动当成目标业务规则
- [ ] 已区分 AS-IS、TO-BE 和 GAP
- [ ] 已标记保留、新增、修改和废弃逻辑
- [ ] 已说明信息冲突来源和采用优先级
- [ ] 已检查页面、角色、权限、状态、数据、接口、口径、迁移、兼容和回滚的适用影响
- [ ] 用户结论覆盖正式规则时已确认其具有相应决策权
- [ ] 决策权来自可信系统角色、正式文档/评审负责人或具名责任人确认，没有只接受自我声明
- [ ] 已通过 `build-safe-file-manifest.py` 建立允许清单，只读取 `allowed` 文件
- [ ] 未读取或回显 `.env`、密钥、令牌、私钥、生产数据和个人敏感信息，也未跟随重解析点读取工作区外内容

## 实现边界

- [ ] 未经用户明确要求没有修改代码
- [ ] 没有擅自新增业务功能、页面或依赖
- [ ] 实现 Demo 前已清空 P0 并明确新增/改造范围
- [ ] 实现前已明确模拟数据和文件范围
- [ ] 没有覆盖正式业务文件或修改无关代码
- [ ] Demo 已评定风险等级，并按低/中/高风险执行对应验证
- [ ] Demo 只使用本地、Mock 或沙箱，没有连接生产环境或产生真实资金、通知、删除、权限变更等副作用

## 非功能与质量

- [ ] 只触发与需求类型匹配的非功能检查
- [ ] 审批/删除/评分/权限已检查日志、审计和追责
- [ ] 数据看板已检查数据源、口径、时间和延迟
- [ ] 外部服务已检查超时、重试、幂等和失败补偿
- [ ] AI 功能已检查失败、安全、成本、响应时间、可解释和人工兜底
- [ ] 产品经理能力复盘仅在用户首次明确要求或正式方案后的后续输出选择中确认后生成
- [ ] 复盘基于本次真实材料、决策和风险；没有空泛表扬、编造遗漏或凑数练习

## 可执行校验

- [ ] 已审查 `skill-creator/quick_validate.py` 与完整 PyYAML 包更新，并仅在确认来源可信后更新 `tests/trusted-tools.json` 中的 SHA-256
- [ ] 已使用显式绝对路径运行 `scripts/validate-release.ps1 -PythonPath <可信 python.exe> -QuickValidatePath <可信 quick_validate.py> -PyYamlPackagePath <可信 yaml 包目录> -BehaviorResultsPath <前向测试结果>`，没有使用 `ExecutionPolicy Bypass`
- [ ] 显式 Python 可执行文件的 Authenticode 签名有效，安全文件清单自检通过
- [ ] 发布脚本已拒绝哈希不匹配的外部校验器或 PyYAML 包，不从 `CODEX_HOME`、`USERPROFILE` 或 `PATH` 自动发现可执行文件与依赖
- [ ] 已对至少一个非页面需求和一个高风险需求执行独立前向测试，并由 `validate-forward-test-results.ps1` 验证原始输出、轨迹与源码指纹
- [ ] 发布校验已依次通过 `validate-skill.ps1`、`validate-behavior-contract.ps1`、`validate-forward-test-results.ps1` 和 `skill-creator/quick_validate.py`
- [ ] 严格 UTF-8、替换字符、活动文档链接、测试编号、行为契约、前向测试结果和关键规则一致性全部通过
