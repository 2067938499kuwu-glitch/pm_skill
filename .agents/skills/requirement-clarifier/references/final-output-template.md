# 最终输出模板

## 使用规则

1. 根据快速、标准、深度模式选择输出内容，不得机械输出全部章节。
2. 已确认、合理假设、待确认、P0 待确认和不在本期必须明确区分。
3. 需求可能涉及已有系统时先记录用户选择的项目关联方式。迭代需求无论是否关联项目，都输出 AS-IS、TO-BE、GAP、信息冲突和变更影响；不关联项目时明确 AS-IS 未经项目核验。全新产品可省略 AS-IS/GAP。
4. 只输出当前需求适用的异常、非功能和实施项，不凭空编造指标、接口或基线。
5. 先识别交付意图：用户要求解析、检查、审查或诊断时使用“评审与诊断模板”，不强制输出完整 PRD；用户要求梳理、设计或形成 PRD 时输出需求方案；原型说明在用户要求页面、交互或原型时输出；Codex 原型提示词只在用户首次明确要求，或正式需求方案后的后续输出选择中确认时输出。
6. 只有目标、角色、主流程、交付载体范围和关键交互或操作明确且无 P0 时，才生成 Codex 原型提示词。
7. 除非用户明确要求实现 Demo，否则本模板只生成文档。
8. 标准模式使用稳定编号，并在规则、交付载体、交互或操作和验收中填写关联编号；深度模式再增加完整追踪矩阵。
9. 标准模式的必选核心为目标与范围、角色权限、主流程与状态、核心规则、主要异常、核心验收和设计总结；页面、接口、迁移、原型和复盘均按适用性或用户意图输出，不得为了填满章节制造内容。

## 正式需求方案后的后续输出选择

快速、标准或深度模式的正式需求方案完成后，如果用户尚未决定是否需要提示词和复盘，在方案末尾只追加选择，不提前生成所选内容：

```text
接下来希望继续生成哪项内容？
A. 两项都生成
B. 仅生成 Codex 交互页面提示词
C. 仅生成产品经理能力复盘
D. 暂不生成
```

执行规则：

- 仅页面或交互类需求且不存在未解决 P0 时显示提示词选项。
- 非页面需求只显示“生成产品经理能力复盘 / 暂不生成”。
- 用户已明确要求或拒绝某项时，不重复询问该项；用户要求简洁输出、不要后续选择、到此为止或同等拒绝表达时直接结束。仅说“完成正式方案交付”不等于拒绝后续输出选择。
- 用户选择后在下一条回复生成对应内容，选择前不自动附加条件模块 C 或 D。
- 不完整草案不得提供可直接实现的提示词选项。
